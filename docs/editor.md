# Editor queries

The core exports synchronous, protocol-neutral queries over a `Revision`. This
page describes the queries in the table and `inlayHintsAt`. In `docs/api.md`,
[Using the body checker](api.md#using-the-body-checker) describes
`sourceHoverAt` and `signatureHelpAt`, and [Capabilities](api.md#capabilities)
describes the definition and document symbol features.

| Query | Result |
| --- | --- |
| `symbolIndex(revision)` | Resolver identities, declaration anchors, occurrences and local scope spans, memoized for that revision. |
| `referencesAt(revision, path, offset, includeDeclaration)` | Declaration, import and use spans across the loaded project. Structural fields and builtins have no reference target. |
| `prepareRenameAt(revision, path, offset)` | The editable name span and original spelling, or no target. |
| `renameAt(revision, path, offset, newName)` | Validated source edits, or a reason the rename cannot preserve binding identities. |
| `completionsAt(revision, path, offset)` | Visible names, prefix replacement spans, record fields and service methods. No automatic imports. |
| `semanticClassifications(revision, path, text)` | Classified source spans with declaration/readonly modifiers. Stale or broken regions use lexical information. |
| `contractActionsAt(revision, path, start, end)` | Validated missing entries for a written `fails` clause and for a `with` clause, from checked body effects. |
| `failsClauseActionsAt(revision, path, start, end)` | One validated action that writes the inferred failure set of the function whose header holds `start` as a `fails` clause. |

Paths are root-relative and offsets/spans count UTF-16 code units. Core queries
have no filesystem or LSP dependency. The occurrence index is held in a weak
cache keyed by the revision, so a later edit gets a new index and does not
keep old indices alive through the program.

Rename follows resolver identities rather than spelling. It re-resolves the
proposed project and compares declaration anchors for every previously indexed
name, including unchanged uses. It rejects reserved names, duplicate bindings,
capture, host-origin symbols and structural field renames. It rejects a rename
when the new project has an analysis diagnostic that the old project did not
have. The comparison uses the code, the source and the span of the diagnostic,
moved through the edits, and it ignores the message. A local referenced
by record shorthand is expanded to `originalField: newName`, preserving the
field. Only Effektive source/interface references are edited; TypeScript is
regenerated by the existing build/save flow. Cross-language TypeScript rename
and moving files are outside this implementation.

A tagged record has the `class` semantic token type, as an error has. Any other type has the `type` semantic token type. The outline lists each `type` declaration as a Struct symbol. Completion offers a type in a type position and a pattern position, and not after `fails`. The TextMate grammar has no rule for the word `nominal`. The semantic tokens mark the uses of a type.

Completion respects local scope, shadowing, type/effect context and partially
typed members. Record unions expose their common fields. Semantic token types
and modifiers are fixed exports; full-document classification includes lexical
comments, strings, numbers, keywords and operators during parser recovery.
There is no delta-token support.

Contract actions apply to written inline function contracts whose checked
bodies and parsed headers are reliable. An action adds a failure only to a
written `fails` clause, because the compiler infers an omitted `fails` clause.
An action adds a missing service to the `with` clause of an export. It preserves
existing entries and resolves effect identities through visible names. When every method of a service
is missing, an action adds the service name. Each action checks the edited
project before it is returned. An action must remove at least one diagnostic and must
add none, by the same comparison. Diagnostic messages are not parsed to generate
edits.
When a written clause holds only `never`, as in `fails never`, the action
replaces `never` with the missing entries.

A second action writes the inferred failure set of a function as a `fails`
clause, such as `fails StoreUnavailable | UserMissing`. It is offered when the
cursor is in the header of a module-level function that has a written result
type, no `fails` clause, and no diagnostic. An empty set gives `fails never`.
The action needs a visible name for each error, and it adds no import. It
checks the edited project: the failure set, the service set, and the execution
mode must not change, and no diagnostic may appear. After the edit, a new
failure in the body gives `failure-contract/001`.

An inlay hint shows the inferred part of a function contract. The hint covers
an exported function and a local function. For an export it shows the inferred
failures, such as ` fails UserMissing`, at the end of the result type and before
a written `with` clause. A function with a diagnostic inside its span has no
hint. This includes a resolver diagnostic, such as an unknown name. A reserved
error has its source name in the hint, such as `SchemaError`.

A contract diagnostic carries related locations: each node of the body that
introduces a missing `fails` or `with` entry. The language server sends them as
`relatedInformation`, so the editor lists each origin under the diagnostic.

Pure behavior regressions are in `tests/editor_queries_test.ts`.

## Language server

The LSP adapter exposes `textDocument/hover`, `definition`, `documentSymbol`,
`references`, `prepareRename`, `rename`, `completion`, `signatureHelp`,
`semanticTokens/full`, `inlayHint` and `codeAction`. Requests flush pending
changes first. Edit requests additionally check current overlays and closed
files against the indexed revision and return versioned `documentChanges`.
A stale request or changed disk source cannot produce an edit.
A contract quick fix has the code action kind `quickfix`, and the fails clause
action has the kind `refactor.rewrite`. A request with `context.only` gets only
the actions of the kinds that it names. Out-of-order
`didChange` versions are ignored. Invalid project configuration disables edits;
semantic highlighting can still fall back to the current lexical text.

Project discovery uses native parent and relative-path operations.
It stops at a filesystem root, including a drive root or UNC share root.
The adapter converts accepted source paths to the core's `/` convention.
The process launcher converts file URLs before it constructs native filesystem paths.
This preserves encoded spaces in a checkout path.

POSIX process checks cover initialization, diagnostics, definition, saving, and shutdown from a checkout path that contains spaces.
Native Windows process validation is outside this reset's acceptance scope and remains unverified.

`tests/lsp_editor_test.ts` covers overlays, UTF-16 positions, reference
inclusion, workspace versions, stale requests/disk, out-of-order changes,
malformed source, quick fixes and invalid request parameters. The installed
VSIX check is a separate release check documented in [installation](installation.md).
