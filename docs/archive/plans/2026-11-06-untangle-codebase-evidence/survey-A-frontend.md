## Root-cause notes
1. A builtin is spread over eight files because each layer keeps its own table keyed by its own spelling of the name. `PRELUDE` (resolve) holds name and shadowing; `NodeFact` (tables) holds the checker's fact; `lower.ts` maps fact to IR; `ROWS`, the `emit/expr.ts` switch and the family files map IR to text; the validator maps IR to checks. One structural fix: a builtin descriptor in a single registry file per family (name, shadowable, fact kind, IR kind, arity) from which `PRELUDE`, the `PreludeCallName` type, the `NodeFact` kind and the kind-to-IR table derive. Then `resolve.ts`, `tables.ts` and the `lower.ts` table stop being edited for each builtin. Emit and validator stay separate on purpose.
2. Lexical vocabulary has no owner. Keywords, contextual words, parser-checked words, reserved names, identifier shape and the keyword enum range are written in `lex.ts`, `parse.ts`, `editor_tokens.ts`, `editor_index.ts`, `editor_completion.ts`, `playground/src/highlight.ts`, and a test. Fix: export one `vocabulary` from `lex.ts` (or `syntax.ts`): `KEYWORDS`, `CONTEXTUAL_WORDS` with a role (declaration, clause, modifier), `PARSER_CHECKED_WORDS`, `isKeywordKind`, `isIdentifier(text)`. `parse.ts`, the editor files, and the playground use it. The tmLanguage test then reads the same list.
3. Identifier and extension grammar lives at call sites. `ids.ts` has only half the constructors (no `capabilityId`, `localId`), and `paths.ts` has `moduleNameOf` but no `isSourcePath`/`isInterfacePath`/`fileModeOf`. Fix: complete both modules so that every id and every extension test goes through them. `parse.ts:fileModeOf` moves to `paths.ts`.
4. `tables.ts` and `modes.ts` both own the effect set. Fix: a small `effect_set.ts` (EffectSet, PURE, EFFECT_ONLY, combine, isQuiet, without) used by `modes.ts` (`Solved` becomes `EffectSet`) and by `check_builtins/*`. `tables.ts` keeps NodeFact/PatternFact/BodyTable, the checker-to-lowering contract. Then builtin changes touch only the contract file.
5. `util.ts` and `frontend.ts` carry non-compiler helpers. Fix: move `canonicalJson` next to `hash.ts`/`sha256.ts` (one "content identity" module that documents that `lower.ts` ids depend on its output); move `errorMessage`, `isRecord`, `sha256Hex` into a small edge-utilities module that host, lsp, playground, bench and scripts import instead of the five private `isRecord` copies. Keep `compareText` and `sortedUnique` with the core ordering helpers. Whether to drop `hash.ts` needs a measurement.
6. Error-name vocabulary (`SchemaError`, `TimeoutError`, `SchemaIssue`, `Defect`) lives in five places (resolve, check_expr, emit/expr, scope, outcome). Fix: one table of effect errors with id, source name, emitted name, and whether the name can be constructed or handled; `EFFECT_ERROR_IDS`, `TARGET_NAMES` entries for them, the `check_expr.ts:1003` ternary and `emit/expr.ts:385` read from it. `TARGET_NAMES` stays separate and is guarded by the slow test.
