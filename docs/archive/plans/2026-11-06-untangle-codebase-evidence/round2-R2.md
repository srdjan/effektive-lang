## Root-cause notes
The refactor removed most of the real problems in this slice. What remains is small and has three causes.

Cause 1, string keys where a union would do: `fieldHelper(key: string)` and the `JSON.stringify` adapter key in the emitter, and the hand-written arity in four layers for the collection builtins. The compiler already checks every other kind-keyed table in this slice (`Rows`, `ShapeTable`, `OPERAND_CALLS`, `PositionalBuilders`), so the gap is where a table uses `string`. One fix per case: a key union for field helpers, and a typed arity record for collections.

Cause 2, a commit message that claims more than the diff: 1094d8d says `LeafCallKind` is derived; `calls.ts` still has the hand list. Other "partly remains" items (C.S1, C.H5, E.N3) are the same pattern: the main move was done and a last user kept the old shape (a test, a constant field, six type-helper imports). A finishing pass for each is one file or two.

Cause 3, files outside the folder that UNF1 and UNF15 cleaned: `core/validate_project.ts` still holds the prelude and host constants and an `isObject` copy. These are the only copies of `paths.ts` and `util.ts` facts that survive in this slice.

Validator internals: no dispatch problem remains. The only repeated shapes are the module fallback span (four copies) and the `DURATION` type literal (three copies), both trivial.

Worth a fix, in order: (1) typed `FieldHelperKey`; (2) `FAMILY_ROW_TABLES` removal and `validate_project.ts` use of `paths.ts` and `util.ts` (trivial, two commits); (3) `LeafCallKind` derivation; (4) the leaf `type_query.ts` for E.N3. Everything else is optional or not worth it.
