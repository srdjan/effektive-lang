## Root-cause notes

Log shapes and file names. The log is one feature spread over `src/host/log.ts`, `src/cli`, `src/lsp/wire_log.ts`, `playground/*`, and `scripts/logs_*`. Kind names, field names, and the file name format exist only as literals in writers and readers. The structural fix is one module (for example `src/host/log_schema.ts`) with a type per kind (`cli.input`, `lsp.fs`, `pg.compile`, ...), a `sessionFileName(surface, day, session)` function with its parser, and a `parseEnvelope` used by both `log_endpoint.ts` and the scripts. Then `prepareLogFolder`, `serve.ts`, `log_endpoint.ts`, `logs_report.ts`, and `logs_replay.ts` read the same types.

Two clients of the same compile result. The LSP (`features.ts`, `projects.ts`) and the playground (`compile.ts`) each turn a `Revision` into diagnostics, generated text with stale marking, hover text, and the `.effi` rule. The fix is to move the stale-output rule, the hover text assembly (`backend` tag to text), and the diagnostic grouping into core editor queries (for example `generatedText(revision, path, previous)` and `hoverText`) so that only the LSP converts to protocol types and the playground to page types.

Offsets and nodes. `covers`, `occurrenceAt`, `targetSpan`/`declarationOf`, `movedSpan`/`movedOffset`, and the speculate sequence are small editor primitives that live in four files. One file (`editor_primitives.ts`: `nodeAt(afterEnd passes)`, `declarationSpan(target)`, `moveThrough(edits)`, `trySpeculative(revision, edits) -> {revision, delta}`) would hold the single version, and `editor.ts`, `editor_index.ts`, `editor_rename.ts`, `editor_actions.ts`, `diagnostic_delta.ts` and `cli/fix.ts` would call it.

Source-file extension. The `.eff`/`.effi` rule is in about 14 places in this slice. A `sourceKindOf(path)` export from `core/paths.ts` (already the owner of module-name and generated-path rules) would replace the inline `endsWith` tests in core editor files, the LSP, `host/workspace.ts`, `host/outputs.ts`, the playground, and a generated constants file or test for `extension.js`.

Save path and output policy. `session.ts` and `projects.ts` each keep a disk program, and `save_round.ts` carries parameters (`removal`, `previous`, `write`, `owns`) that only mark which caller is asking. A `DiskProject` object in `src/host` (workspace read, diff, program update, save round, held-module reasons) used by the CLI session and the LSP would remove the second program-feeding loop and move `heldReason` next to `writableModules`.

Cycles. Both are type-only and come from putting shared types in the file that also holds values (`ServerContext` in `server.ts`, `FileFailure` in `io.ts` and `EventLog` in `log.ts`). Move the types to `lsp/handler.ts` and a small `host/ports.ts`.
