## Root-cause notes
The refactor removed the main cause of slice H (no shared module). What is left is small: `bench/m2.ts:553` is the one place where the pair rule was not moved, and `withTempDir` carries one option that no caller uses. Both are one-file edits.

## Tests

Method. I scanned the 262 files of `testpass-untouched.txt` with a pattern scan (`assertNotEquals`, constant assertions, `.length` equals a number, loops over file-system or fixture sets, call-order arrays, `Reflect`, `as unknown as`, expected values computed with `src` helpers) and a block scan (tests with only `assert(` and `.ok` or `!== undefined` arguments; tests with no `assertEquals`). I read about 45 candidates. I did the fault injections in `<scratch>` (a `git archive` copy of HEAD), never in the repository. No pattern found `assert(true)`, `assertEquals(x, x)`, or `assertExists`. No test reads a field that starts with `_` or `.cache`. The empty-set loops over directories (`tests/core_boundary_test.ts`, `tests/emit_families_test.ts`, `tests/validate_test.ts:545`, `tests/docs_test.ts:42`, `tests/surface_test.ts`, `tests/validate_test.ts:975`) all have a size guard or a census over a named list. I did not read the other files in the 262; the scan is the evidence for them.

Confirmed findings, most certain first.

- T1. `tests/pairs_test.ts:11` ("byTurn maps the run order of a turn back to the pair A, B"). Kind: cannot fail on a real regression. The test calls `byTurn(1, "A", "B")` and then `byTurn(1, first, second)`. Fault injected: `bench/pairs.ts` changed to `return [x, y]` (never swaps), and in a second run to the inverted rule. In both runs the test at `:4` fails and the test at `:11` passes. With the identity function the round trip also holds, so the test proves nothing the literal rows at `:4` do not prove. Fix: delete the test.
- T2. `tests/bench_m7_test.ts:82` ("the M4 disk configuration differs from M4 only in writeOnSave"). Kind: repeats the implementation. The expected value is `{ ...m4Config(profile), writeOnSave: true }`, which is the body of `m4DiskConfig` (`bench/profile.ts:164-166`). Fault traced: any change of a field in `m4Config` (steps, size, documents) leaves the test green; only dropping the spread or the flag fails it. Fix: assert `m4DiskConfig("quick").writeOnSave === true` and a literal full object for one profile, or delete.
- T3. `tests/bench_m7_test.ts:62` ("the M7 profiles cover every preset..."). Kind: tied to constants. It asserts `M7_SCENARIOS.length` is 6, that every preset has positive counts, that the large `full` steps exceed the `quick` steps, and the preset order. These restate `bench/profile.ts` data. Fault traced: a wrong `full` step count that is still larger than the `quick` count passes; a deliberate change of the scenario count fails with no bug. Fix: keep the preset-order check, drop the count and the `>` checks.
- T4. `tests/lex_escape_test.ts:17` (`assertEquals(text.length, 5)`). Kind: cannot fail. `text` is the literal `'"\\\u{1F600}"'` declared two lines above. The assertion checks the test's own constant. Fix: delete the line (the comment at `:16` carries the same fact).
- T5. `tests/concise_source_test.ts:363` ("resource expressions retain scopes, data-only results, finalizer contracts and nested capture rejection"). Kind: cannot name its fault. The loop asserts only `diagnostics.length > 0` for nine sources. I printed the codes in the copy: the first two sources give `unknown-name/001` (a name `job` or `local` that is not in scope, not the rule in the test name); the others give `type-mismatch/010`, `type-mismatch/003`, `syntax/008`. A regression that replaces the scope rule or the finalizer rule by any other diagnostic keeps the test green. Fix: use a table of source and exact code, as `tests/lsp_jsonrpc_test.ts:124` does.
- T6. `tests/sourcemap_test.ts:223` and `tests/sourcemap_test.ts:283` (the source position of each mapped offset, and the position of `UserMissing`). Kind: repeats the implementation. The expected line and column come from `positionOf(lineStarts(...))` (`src/core/source.ts:44`), the function that the encoder `src/core/emit/sourcemap.ts:99,121` also uses. Fault injected in the copy: `lineStarts` pushes `i + 2` for the fourth line start. `deno test -A tests/sourcemap_test.ts tests/spans_test.ts` gives 24 passed, 0 failed. Fix: keep the decoder, and take the expected positions at `:283` from literals (line and column of `UserMissing({ id })` in the fixture text), and compute them at `:223` by a local line scan in the test support file.
- T7. `tests/output_characterization_test.ts:40` (`assertNotEquals(outputs.emitted(broken.value, "main"), emitted)`). Kind: only a difference from the wrong value. It says the result differs from the earlier success, not that it is the expected failure. Fault traced: any change of the broken result, including a crash value or a second success with other text, passes. Fix: assert the exact `{ ok: false, error: ... }` value that the next assertion at `:41` already implies.
- T8. `tests/docs_test.ts:125` (`assertEquals(cited.length, 7)`). Kind: tied to the layout of a document. The count is the number of rows in a table of `docs/architecture.md`. A new correct row fails the test, and a deleted row with a deleted test passes it. The loop after it is the real check. Fix: assert `cited.length > 0`.
- T9. `tests/ir_snapshot_test.ts:5` loop `for (const { files, modules } of corpus)`. Kind: loop over a set that may be empty. If `fixtures/ir/examples-baseline.json` held `[]`, the test passes with no assertion. Fault traced, not run. Fix: add `assertEquals(corpus.length, 2)` (the count written by `scripts/golden_update.ts`).
- T10. `tests/defect_test.ts:83` ("Defect is reserved as a declaration name"). Kind: weak oracle (low). It asserts that some message includes the text `Defect`. Any diagnostic that mentions the name passes, including a type mismatch. Fix: assert the exact reserved-name code for the three sources.
