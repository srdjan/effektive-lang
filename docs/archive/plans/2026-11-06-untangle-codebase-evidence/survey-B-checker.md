## Root-cause notes

Cycle `types.ts <-> type_ir.ts`. `type_ir.ts` needs only the public methods of `TypeTable`, and imports it as a type. `types.ts` imports two functions back. Use one: `TypeTable.load` (import of an IR graph) is IR-to-table conversion and has no reason to be a table method; move it to `type_ir.ts` (or a new `type_graph.ts`) as `loadGraph(table, graph)`. Use two: `union()` sorts by `canonicalJson(typeToIr(...))`. Replace that sort key with a key built from the node itself, or accept a key function injected at construction. This also fixes `DefinitionSource` vs `TypeGraph` and puts `guardedRecord` and `tagOf` with the import logic that uses them.

Cycle `infer_inputs.ts <-> check_expr.ts`. It is one type-only import: `BodyEnv`. Moving `BodyEnv` into `signatures.ts` (beside `TypeEnv`) removes the cycle with no logic change. `check_project.ts` also stops importing it from the largest checker file.

Shadow walkers. `InputEngine` (`infer_inputs.ts`), `BodyChecker.markCheckedSlots` and `BodyChecker.expr` are three walkers over one expression grammar, each with its own idea of "the type of a name", "an option element", and "the construction target of a type". One fix would be a small `expression_shape.ts` in the checker layer holding the shape decoders (call: callee and args; pipe: left, stage, args; field: base and member; arrow: params, result, clauses; field parts of a record). Callers keep their own traversal and reuse the decoders. Pieces that would then live together: the six `parts.find` copies, the four `FieldExpr` copies, the two arrow parameter parsers, and `fieldParts`.

Nominal-id predicates. About a dozen sites ask what a named id stands for (error, tagged record, identity, alias) and each re-derives it from `isErrorId`, `taggedRecordOf`, `identityBaseOf`, `aliasOf`, `errorRecordOf`. Add two methods to `TypeTable`: `isNominalData(id)` and `recordBodyOf(id)`. Pieces that would then live together: the items under Hidden links 1 and 2.

Reserved and builtin names by string. `Some`/`None`, `Defect`, the three reserved errors, `Duration`/`Instant`, and the modifiers `sealed`/`opaque`/`borrow`/`pure` are all recognised by name or id at the point of use. The resolver and the declaration index already read these names once. Have them publish the result (a `builtin` target with an `option-constructor` role; a `reserved: true` flag on the error declaration; modifier flags on `DeclEntry`) and let the checker read the flag. Pieces that would then live together: the eight `Some`/`None` branches, the `Defect` branches, the four modifier detectors, and the reserved error triple.

Rule 11 split. `guardedRecord` (types.ts), `recursionIsGuarded` (type_lower.ts), `literalTag` and `tagOf` (check_declarations.ts, types.ts) belong in one `recursion_guard.ts` that takes an alias lookup. Both `load` and `checkCycles` would call it.
