# Survey: slice E, emitter (src/core/emit/, src/core/emit/families/)

All files in the slice were inspected at the level of exports, imports and the hot spots named in the task. Not read line by line: the bodies of `expr.ts` (1891 lines), `decls.ts` (1067), `doc.ts` (668), `sourcemap.ts` and `families/schema.ts`.

## Hidden links
- **E.H1** `emit/emit.ts:115-171` (+ `emit/module_state.ts:459-540`, `emit/module_state.ts:697-741`): `ModuleState` is mutable naming state that records on first use. `nameOf`, `effect`, `intFunction`, `unmatched`, `outcome`, `hostCheck`, `intSchemaName` and `fresh` add names and imports as a side effect of being called. So the order in `build()` is a contract that only comments state: (1) print all declarations, (2) `hostAssertions()` (they register `$Int` and `$hostCheck`), (3) helper declarations in the fixed order of `helperDeclarations`, (4) `fieldHelperDeclarations` (it calls `scope.fresh("$fields")`, `fields.ts:84`), (5) read `effectImports`, `moduleImports`, `hostImports`. A helper declaration that calls `scope.effect(...)` (for example `outcomeDeclaration`, `outcome.ts:15`) must run before step 5. `usesHelper` must run after step 2. Nothing in the types prevents a wrong order; a reorder changes names and imports silently. The `ImportLedger` interface (`module_state.ts:245`) documents "reads after all printing" only in a comment.
- **E.H2** `emit/decls.ts:1057` (+ `emit/emit.ts:190-205`, `emit/doc.ts:97`, `emit/spans.ts:25-29`): the host assertion ranges travel by a string key. `decls.ts` wraps the statement in `marked(host.hostName, ...)`. `emit.ts` then rescans `rendered.marks` and `scope.hosts` to match `hostName === mark.key` and rebuilds a `HostAssertionRecord`. `spans.ts` copies the records again into `HostAssertionEntry`, and `tsc.ts` finds them by offset. One concept (the assertion range) is rebuilt in three places and keyed by a generated name.
- **E.H3** `emit/decls.ts:577`, `emit/expr.ts:902`, `emit/fields.ts:8` (+ `fields.ts:11-17`): the literal `"__proto__"` is checked in three places. `fieldKey` already handles it, but `decls.ts:577` and `expr.ts:902` re-test the name. `sensitiveField` has the literal list `["message","name","stack"]` (`fields.ts:17`). A new unsafe property name needs edits in all three.
- **E.H4** `emit/module_state.ts:630-638`, `emit/expr.ts:385-386`, `emit/expr.ts:1421`, `emit/expr.ts:1822-1825`, `emit/families/schema.ts:129`, `:154`, `:351`: the identities `"error:effect/SchemaError"`, `"error:effect/TimeoutError"` and `"error:effect/SchemaIssue"` are string literals in the emitter. `ir.ts:11-14` already exports `SCHEMA_ERROR_ID`, `SCHEMA_ISSUE_ID` and `TIMEOUT_ERROR_ID`, and the checker uses them (`check_builtins/schema.ts:2`). The emitter knows how to name each of these (`module_state.nameOf`, `expr.errorTag`, the issue test in `expr.ts:1421`) in separate places. A new reserved Effect error needs edits in `ir.ts`, `types.ts:429`, `validate/world.ts:108`, `module_state.ts:630`, `expr.ts:385` and the match and catch paths.
- **E.H5** `emit/shape.ts:62-190` (+ `emit/calls.ts:38-92`, `emit/expr.ts` dispatch): the `leaf` marker in `ROWS` and the kinds in `LEAF_CALLS` / `OPERAND_CALLS` / the `*LeafKind` unions in `families/*.ts` must agree. `LeafCallKind` (`calls.ts:68`) is a hand list of leaf kinds; nothing ties it to `ROWS[...].leaf === "leaf"`. The comment says "the compiler rejects a kind that has neither", which holds only for the structural half. Probable; check by adding a kind to `LeafCallKind` that `ROWS` marks `structural` and see whether the compiler rejects it.
- **E.H6** `emit/emit.ts:176`, `emit/module_state.ts:379`, `:358`, `:364`, `:365`, `:393` (+ `paths.ts:33`, `:40`, `parse.ts:48`, `validate/refinements.ts:452`): the emitter re-derives "this module is a companion (.effi)" with `endsWith(".effi")`, "this import is the prelude" with `=== "effektive:prelude"` (`validate/world.ts:48` has its own `PRELUDE_MODULE`; `lower.ts:1592` another literal), and "this import is a host" with `startsWith("host:")` plus `slice("host:".length)`. `paths.ts` and `project.ts` hold the same facts.

## Root-cause notes
The answers to the task's questions. (1) `module_state.ts`: yes, it is shared mutable state with a call order that callers must know (see the first Hidden link). It is consistent with its own design ("records the name on first use"), but the contract is only in comments. (2) `doc.ts`: no finding beyond the host-assertion `marked` key protocol; all exports have users. (3) `failure.ts`: the class itself is fine; the exception leaks to `typescript.ts` for hover. (4) `shape.ts` / `expr.ts` / `families/*`: the split is clean in imports (no family imports `expr.ts`), but `calls.ts` and `shape.ts` each hold a kind list that must agree with the other and with `expr.ts` dispatch. (5) `tsc.ts` / `spans.ts`: no copied span logic found. `tsc.ts` calls `offsetOfGenerated`, `mapOffset`, `hostAssertionAtOffset` from `spans.ts`; `sourcemap.ts` calls `recordAtOffset` and `zeroBasedPosition`. `spans.ts` delegates line arithmetic to `source.ts` (`lineStarts`, `lineIndexOf`). The only link issues are the `EmittedModule` type import and the host-assertion record copy.

Cause A, reserved Effect knowledge as string literals: the three Effect error ids, `"__proto__"`, `.effi`, `effektive:prelude`, `host:` are written as literals across `module_state.ts`, `expr.ts`, `families/schema.ts`, `decls.ts`, `emit.ts` while `ir.ts` and `paths.ts` already own constants or helpers. Fix: use the `ir.ts` constants and add predicates (`isCompanionPath`, `isHostLabel`, `isPreludeModule`) to `paths.ts`. Then one change to a reserved name stays in one file.

Cause B, naming state doubles as a two-phase ledger: `ModuleState` both allocates names during printing and serves as the import list afterwards, with a call order held in `build()`. Fix: split it into `NameAllocator` (fresh, temp, helper names, effect aliases, `nameOf`) and a `ModuleImports` result that `build()` can only obtain by calling `scope.finish()` after printing. Then reading imports before printing ends is a type error, and `sourcemap.ts` no longer imports the allocator for `relativeSpecifier` (move it to `paths.ts` next to `generatedPathOf`).

Cause C, one concept rebuilt across modules: the host assertion record (`decls.ts`, `emit.ts`, `spans.ts`) and the helper declarations (`decls.ts` methods plus `outcome.ts`). Fix: have `DeclarationEmitter.hostAssertions()` return the records with their offsets directly (`marked` carries the record, not a name), and move the five helper declarations into one `helpers.ts`. Then `emit.ts` stops matching by `hostName`.

Cause D, per-kind walkers over `Type` and `Expr` in several files: six switches over `Type` kinds and a leaf-kind list in `calls.ts`. Fix: one `type_walk.ts` in `emit/` with a fold over `Type` (named-follow with the `seen` guard) and derive `LeafCallKind` from `ROWS`. This stays within the emitter and does not touch the validator, which keeps its own walker on purpose.

Cause E, test-only code in `src`: the source map decoder (`decodeMappings`, `decodeVlqList`, `lookupMapping`, `encodeVlq` if only tests use it) and `mapGenerated`. Fix: move it to `tests/` helpers, or keep and mark it as the oracle. Check: `git grep -w lookupMapping -- src` shows `emit/sourcemap.ts` and `typescript.ts` only.
