## Root-cause notes
Wiring of families is good. `expr.ts:676-815` is one exhaustive switch (TypeScript-checked), each family exports plain functions `(c: ValidatorCore, e, path) -> Comp`, and families import only `context.ts`, `typing`, `sets`, `report`, `expr_walk`. There is no dispatch table, but one is not needed: the switch is the registration. The cost is that a new node kind needs `exprChildren`, `compute`, `markCheckedRaw`, and possibly a `ValidatorCore` method. That coupling is real but small and mostly compiler-checked.

Cause 1, Ctx lives in the wrong file. Ctx/World (tiny) are in world.ts, which also holds 1200 lines of checks. This causes the refinements<->world cycle and the `families/context.ts -> world.ts` edge. Fix: move `World` and `Ctx` into a lookup-table module with `buildWorld`; split the check groups (type ids, declarations, recursion, imports) into their own files. Then `refinements.ts` and families import only the table module.

Cause 2, no shared bounded type walk. Five walkers in world.ts and four alias-following containment walkers in typing.ts/expr.ts/refinements.ts each re-implement the depth bound, the cycle guard, and the `addDepth` call. Fix: one `walkType(type, path, visit)` helper beside `typeChildren` (type_children.ts) that owns `MAX_DEPTH` and the depth report. Then `MAX_DEPTH`, `typeChildren`, and the one-report-per-declaration rule live together.

Cause 3, builtin identities are not one table. The reserved error ids (Schema, SchemaIssue, Timeout), Duration, and Instant are tested in three places and seeded in a fourth, partly with string literals. Fix: one `PRELUDE_DECLS` list in typing.ts used both to seed `buildWorld` and to answer `isReservedError`.

Cause 4, effect-state helpers are scattered. `Active` constants and literals live in sets.ts, context.ts, expr.ts and four families. Fix: put `QUIET`, `EFFECT_ONLY`, and an `effectOf(failures, requirements)` constructor in sets.ts; keep `Out` and `Comp` with BodyValidator rather than in families/.
